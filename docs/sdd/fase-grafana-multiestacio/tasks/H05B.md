# H05B — Resoldre semàntica de pressió i pluja Grafana

## Objectiu

Determinar amb evidència suficient si:

- `xoic_I2CAT_pressio`
- `xoic_I2CAT_pluja_acumulada`

es poden mapar de manera segura als camps canònics MeteoLord.

Aquesta tasca és exclusivament d'investigació.

NO modificar:
- backend funcional
- frontend
- BD
- schema
- snapshots
- migracions

NO avançar H05C ni H06.

---

## Baseline

Utilitza:

- `STATE.md`
- `evidence/H04-grafana-metrics.json`
- `evidence/H05A-validation.json`

No repetir H01–H05A.

- temperatura -> `temp_c`

# A. PRESSIÓ

Mètrica:

`xoic_I2CAT_pressio`

Cal determinar amb evidència:

1. unitat real;
2. rang observat;
3. si és:
   - pressió absoluta/local;
   - pressió relativa;
   - pressió corregida a nivell del mar;
   - una altra magnitud;
4. si Grafana aplica transformació;
5. origen de la dada si es pot identificar;
6. camp canònic MeteoLord apropiat.

No decidir només perquè els valors "semblen hPa".

## Evidència prioritària

En ordre:

1. configuració/query/panell Grafana;
2. labels/metadades de la sèrie;
3. documentació del sistema/font que produeix la mètrica;
4. documentació del dispositiu només si el model del dispositiu està demostrat;
5. comparació numèrica només com a evidència auxiliar, mai com a prova única.

## Mostres

Obtenir mostres mínimes de diverses estacions i altituds si aquestes
altituds estan documentades.

Registrar:

- external_id
- timestamp
- valor
- unitat declarada, si existeix
- evidència semàntica

No inferir el tipus de pressió exclusivament per l'altitud.

## Resultat

Una de:

- `CONFIRMED_ABSOLUTE`
- `CONFIRMED_RELATIVE`
- `CONFIRMED_SEA_LEVEL`
- `SEMANTICS_UNRESOLVED`

Només si és CONFIRMED proposar `canonical_field`.

---

# B. PLUJA

Mètrica base:

`xoic_I2CAT_pluja_acumulada`

Query actual del dashboard:

`current - offset 1d`

Cal determinar:

1. unitat de la mètrica base;
2. què representa exactament el counter;
3. si és:
   - acumulat des d'arrencada;
   - acumulat des de reset;
   - acumulat diari;
   - un altre acumulador;
4. quan i com es reseteja;
5. comportament quan hi ha reset dins les 24 h;
6. si pot disminuir;
7. si `current - offset 1d` és realment equivalent a precipitació 24 h;
8. camp canònic MeteoLord apropiat, si existeix.

No assumir que la unitat és mm.

No assumir que:

`counter(t) - counter(t-24h)`

és sempre correcte si el counter pot reiniciar-se.

---

# C. ANÀLISI DE RESETS

Per una mostra representativa d'estacions amb pluja:

analitza suficient historial per detectar:

- disminucions del counter;
- retorns a zero;
- discontinuïtats;
- valors negatius de la query 24 h.

No cal descarregar dades innecessàries.

Resumeix:

- resets_detected
- negative_deltas_detected
- behavior

Si no hi ha prou historial per descartar resets:

`RESET_BEHAVIOR_UNRESOLVED`

# E. NO FER INFERÈNCIA PER NOM

El fet que una mètrica es digui:

`pressio`

o

`pluja_acumulada`

no és evidència suficient per decidir:

- unitat;
- correcció;
- semàntica exacta.

# G. CRITERI PER H05C

H05C només es pot autoritzar per una variable si:

- unitat confirmada;
- semàntica confirmada;
- mapping canònic inequívoc.

Per pluja, a més:

- comportament davant reset resolt;
- transformació 24 h matemàticament defensable.

Una variable pot quedar bloquejada sense fer fallar H05B.
