# H05A — Snapshot Grafana multivariable confirmat

## Objectiu

Ampliar la integració Grafana existent perquè `fetchSnapshot(binding)`
incorpori les dues variables amb contracte completament confirmat:

- temperatura → `temp_c`
- humitat relativa → `humitat_pct`

NO integrar encara pressió ni pluja en camps canònics.

Preservar tota la funcionalitat G01–G07.

No avançar H05B/H05C ni H06.

---

Utilitza:

- `STATE.md`
- `evidence/H04-grafana-metrics.json`

No repeteixis H01–H04.

metric:

### Humidity

# 3. TIMESTAMPS PER CAMP

H04 ha demostrat que les variables poden tenir completitud diferent.

NO assumeixis que temperatura i humitat comparteixen sempre timestamp.

Per cada variable conserva internament el timestamp real de la seva
última observació vàlida.

Reutilitza el model/quality existent si ja suporta timestamps per camp.

Si no existeix suport:

- fes el canvi mínim no destructiu;
- evita migració si es pot representar dins `quality_json`;
- documenta clarament el contracte.

El `observedAt` global no ha de fabricar simultaneïtat.

Defineix explícitament com es deriva a partir dels camps disponibles.

Preferència:
utilitzar l'instant de referència compatible amb el contracte actual,
sense perdre els timestamps individuals.

---

# 4. VALIDACIÓ DE TEMPERATURA

Conserva íntegrament els casos G02:

- zero vàlid;
- null;
- NaN/no numèric;
- timestamp invàlid;
- timestamp futur;
- sèrie ambigua;
- observació contradictòria;
- unitat no declarada.

No regressar el contracte ja validat.

---

# 5. VALIDACIÓ D'HUMITAT

Humitat:

- `0` és vàlid;
- `100` és vàlid;
- null és absent;
- valor no numèric és invàlid;
- < 0 és invàlid;
- > 100 és invàlid.

No clampis silenciosament.

Exemples:

- `-1` → rebutjat
- `101` → rebutjat
- `0` → vàlid
- `100` → vàlid

Un error d'humitat no ha de descartar una temperatura correcta.

La qualitat ha de ser per camp.

---

# 6. ABSÈNCIA PARCIAL

Casos vàlids:

temperature AVAILABLE
humidity MISSING

o:

temperature MISSING
humidity AVAILABLE

No fallis tot el snapshot perquè una variable opcional falti.

Només considera que no hi ha snapshot útil si no existeix cap variable
canònica vàlida.

---

# 7. PERSISTÈNCIA

Reutilitza `current_snapshots`.

No crea:
- taules;
- migracions;
- històric.

El snapshot ha de contenir:

- temp_c quan existeixi;
- humitat_pct quan existeixi;
- resta de camps canònics igual que ara.

No escriure `meteo.mesures`.

---

# 8. MONOTONIA PER CAMP

No permetis que una observació antiga d'humitat substitueixi una
observació més nova del mateix camp.

No permetis tampoc que una resposta parcial elimini un valor recent
vàlid d'un altre camp sense justificació.

Exemple:

Snapshot existent:
- temp 15:30
- humidity 15:30

Nova resposta:
- temp 15:45
- humidity 15:15

Resultat:
- temp → actualitzar
- humidity → conservar la més recent vàlida

No aplicar monotonia només al timestamp global si això provoca pèrdua
de dades per camp.

---

# 9. CADÈNCIA GRAFANA

H04 ha observat una cadència modal real de:

`900 segons`

mentre la configuració actual usa:

`300 segons`

Abans de modificar aquest valor:

1. verifica la cadència en una mostra representativa de sensors;
2. confirma que 900 s és el comportament normal de la font i no només
   de les tres estacions de H04.

Si queda confirmat:

- conserva configuració override;
- canvia el default/documentació de Grafana a 900 s;
- actualitza tests de frescor.

Si no queda prou demostrat:

- NO canviïs el default;
- documenta `CADENCE_REVIEW_REQUIRED`.

No inventis una cadència.
